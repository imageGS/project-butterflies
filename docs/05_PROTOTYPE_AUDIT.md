# 05 — АУДИТ ПРОТОТИПА

> Отвечает на вопрос «что у нас уже есть и что с этим делать».
> Прототип — не база для развития, но **источник**. Здесь расписано, что из него забираем.

---

## 1. Что представляет собой прототип

2D-рейкастер на GDScript (Godot 4.x). Рабочая играбельная демонстрация атмосферы, правил и интерфейса.

**Масштаб:**
- ~11 400 строк GDScript в 56 файлах;
- 1121 файл в репозитории;
- 460 импортируемых ассетов;
- 5 станций, 2 именных NPC, 8 предметов, 11 шейдеров.

**Что он доказывает:** тон, цикл, интерфейс, систему взаимодействия и диалогов — всё это работает. Атмосфера передаётся.

**Что он не может:** расти. См. `04_TECH_DIRECTION.md` п.1.

### 3.2. Тексты и данные — забрать

| Что | Файл | Ценность |
|---|---|---|
| Тексты предметов | `resources/items/items.json` | Названия, описания, **флейвор-тексты** — эталон тона |
| Диалоги | `dialogues/kitsu/main.json`, `wanderer.json`, `intro.json` | Готовая структура диалогов и ветвления |
| Лор | `DESIGN.md` | Мир, персонажи, конфликт — источник для `02_WORLD_NARRATIVE.md` |

### 3.3. Дизайн-решения — забрать

Проверенные в бою идеи, которые работают и должны жить дальше:

- **Контекст-меню** по удержанию ПКМ с иконками действий и hover-scale;
- **Матрица «глагол × объект»** — основа свободы действий;
- **Три столпа иммерсив-сима** — иммерсивность, системность, эмерджентность;
- **Правило «≥3 ортогональных решения»** для каждой заготовленной ситуации;
- **Проверки как модификатор, а не затвор**;
- **Шум и свет как законы мира**, а не как механика уровня;
- **Awareness** — пассивная интуиция по таймеру;
- **Персистентность мира** между циклами;
- **Сон = сохранение = продвижение главы**;
- **Флейвор-тексты предметов** — конкретные, бытовые, страшные и смешные одновременно.

## 5. ЛОВУШКИ при работе с прототипом

### 5.1. `enum Type` — позиционный

```gdscript
enum Type { ENEMY, NPC, ITEM, OBJECT }   # значения: 0, 1, 2, 3
```

А в `.tres` станций записаны **числа**:

```
resources/stations/shelter.tres:10  type = 3    # OBJECT
resources/stations/shelter.tres:44  type = 1    # NPC (Китсу)
```

**Если просто убрать `ENEMY` из начала** — `OBJECT` станет `2`, `NPC` останется `1`, и **все 9 объектов в убежище превратятся в ничто**. Сцены поедут молча, без ошибок.

**Правильно:** фиксировать значения явно.

```gdscript
enum Type { NPC = 1, ITEM = 2, OBJECT = 3 }
```

### 5.2. `Item` НЕ боевой

`scripts/scenes/item.gd` лежит в «боевой» папке, но это `class_name Item` — на нём держится вся предметная система: `ItemCatalog`, `InventoryGrid`, инвентарь 6×5, бросок предметов, подбор.

Используется в `dungeon_gameplay`, `interaction_system`, `hud_system`, `inventory_panel`. **Удалять нельзя.** Структурно стоило бы перенести в `scripts/resources/`.

### 5.3. `PlayerStats` — резать частично

**Боевое (удалять):**
- `_limb_snapshot`, `save_limb_state()`, `restore_limb_state()`, `create_combatant()` — вызывает только `main.gd`;
- `_pending_corpse` — писалось из боевой ветки и `dungeon_gameplay`, читалось в `entity_manager`.

**Живое (оставлять):**
- `health`, `sanity`, `humanity` — читают `stats_panel`, `skill_check`;
- `take_damage()` — вызывается из `interaction_system` для ловушек;
- инвентарь, флаги, навыки, `cycle`, `death_count`.

### 5.4. `glass_shatter.gdshader` — не боевой

Используется в `intro.tscn` — сцена со стеклом. Скриптованная сцена, не боевая система.
