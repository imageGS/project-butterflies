# ⚠️ ГЛАВНОЕ ТРЕБОВАНИЕ

## Всё собирается через сцены Godot

**Каждый уровень — сцена. Каждый объект — инстанс сцены. Всё видно в редакторе и двигается мышкой.**

Это условие приёмки. Если объект нельзя выделить, подвинуть и настроить в редакторе — задача не выполнена, независимо от того, работает ли код.

**Почему так:** в прототипе станции строились из данных в рантайме (ASCII-карта + `StationData`, `MapManager` собирал геометрию, `EntityManager` спавнил сущности-словари в массив). В редакторе не было видно ничего. Нельзя было подвинуть стену, не пересчитав ASCII. Из-за этого проект стал тяжело развиваемым.

**Как правильно:**

```
station_akio.tscn          ← открыл, увидел всю станцию целиком
├── Geometry (Node3D)
│   ├── Floor / Walls / Ceiling     MeshInstance3D
│   └── StaticBody3D                коллизии
├── Objects (Node3D)
│   ├── Door_Service                инстанс door.tscn
│   ├── Locker_A                    инстанс locker.tscn
│   └── Container_B                 инстанс container.tscn
├── Characters (Node3D)
│   └── Kitsu                       инстанс kitsu.tscn
├── Lights (Node3D)
│   └── EmergencyLight_01           OmniLight3D
└── Markers (Node3D)
    ├── PlayerSpawn                 Marker3D
    └── Exit_ToShelter              Marker3D
```

**Чего делать нельзя:**

| Нельзя | Почему |
|---|---|
| Строить уровень кодом в `_ready()` | В редакторе пусто, нельзя подвинуть не переписав код |
| Хранить объекты массивами словарей | Не узлы: не видны, не выделяются, не настраиваются |
| Загружать геометрию из `.txt` / `.json` / `.tres` | Та же ошибка, что в прототипе |
| Спавнить объекты из «таблицы спавнов» | Дверь должна лежать в сцене, а не создаваться из координат |
| Держать поведение в константах скрипта | Заменить на `@export` — тогда правится в инспекторе |

**Настройка — через инспектор, не через правку скрипта:**

```gdscript
@export var door_id: String = ""
@export var is_locked: bool = true
@export var needs_keycard: bool = false
@export var break_force: int = 3
@export var noise_radius: float = 4.0
```

Один `door.tscn` → десять разных дверей на станции, каждая настроена мышкой в инспекторе.

**Данные в `.res` / `.json` допустимы** — для диалогов, текстов предметов, конфигов. **Но не для геометрии и не для расстановки объектов.**

**Проверка перед сдачей:**

- [ ] Станция открывается как `.tscn` и **видна целиком**
- [ ] Стены, пол, объекты, свет, NPC — **отдельные узлы**, выделяются
- [ ] Объекты **двигаются мышкой** и не ломаются
- [ ] Свойства меняются **без правки скрипта**
- [ ] Запуск из редактора даёт то, что видно в редакторе
- [ ] **Нет кода, который строит уровень в рантайме**

Полные правила с примерами и приёмами — `docs/SCENE_ARCHITECTURE.md`. Прочитать целиком до начала работы.

## Задача

**Собрать работающий 3D-проект.** Не прототип рендера, не архитектурный каркас — играбельный срез.

начинай с вертикального среза (`06_ROADMAP.md`, этап 1). Не мигрируй все системы сразу.

### Станция вертикального среза

```
комната убежища (тёмная, один аварийный источник света)
   → короткий тоннель, два поворота
   → запертая дверь
   → боковая комната с контейнером
   → возвращение в убежище
```

Всё это — **сцена**, собранная в редакторе.

### Что должно работать в срезе

| Механика | Детали |
|---|---|
| **Движение** | `CharacterBody3D` + `Camera3D`, обычный mouse-look, WASD, Shift — бег |
| **Фонарик** | `SpotLight3D` на камере, имеет заряд, заряд тратится |
| **Спрайтовый NPC** | Китсу, `Sprite3D` billboard, 4 направления по вектору камера→персонаж |
| **Предмет на полу** | Подобрать — с проигрыванием анимации руки |
| **Контейнер** | Открыть, своя сетка предметов |
| **Дверь** | Три состояния: заперта / открыта / выбита |
| **Шум** | Брошенный предмет создаёт событие, мир реагирует |
| **Диалог** | Один разговор с Китсу: ветвление, портрет-эмоция, печать по буквам |
| **Сохранение** | Сохранить и загрузить состояние сцены |
| **Пиксельный вид** | Пониженное разрешение вьюпорта, `Nearest`, CRT-шейдер поверх |

**Критерий готовности:** можно играть 5 минут и не хочется закрыть.

## Ассеты: правила работы

**Ассеты приходят от автора готовыми к использованию.**

- **Не масштабировать, не уменьшать, не пикселизировать, не перекрашивать.** Использовать как есть.
- Если ассет не подходит — **сказать автору, что нужно**, и продолжить на том, что есть. Не подгонять самостоятельно.
- Запрос формулировать словами: «нужен спрайт двери, 4 направления, ~150×250».

**Настройки импорта:** фильтрация `Nearest`, мипмапы выключены. Это единственное, что нужно сделать с картинками.

## Технические решения — утверждены

| Решение | Значение |
|---|---|
| Движок | **Godot 4.7**, Forward+ (как в прототипе) |
| Пространство | Настоящее 3D |
| Персонажи и объекты | **Спрайты** — billboard. Как в Doom / Duke Nukem 3D / Blood |
| **Сборка мира** | **Только сцены Godot.** Всё видно и двигается в редакторе |
| Структура персонажа | `Sprite3D` с `billboard_mode`, направление по вектору от камеры |
| Интерактивные объекты | Базовый класс `Interactable` — объект **сам сообщает** доступные действия. Никаких `if type ==` по всему коду |
| Уровни | Сцены `.tscn`. **Не** автоконверт ASCII-карт |
| Состояние мира | Персистентно: брошенное лежит, вскрытое вскрыто, выбитая дверь выбита |
| UI | `CanvasLayer` поверх, пониженное разрешение вьюпорта, `Nearest` |
| Постобработка | CRT — **последним слоем**. Сцена должна читаться без него |

## Ограничения

- **Боёвки нет. Врагов нет.** Не изобретать, не восстанавливать, не оставлять заглушек. Будущая система столкновений проектируется отдельно, позже.
- **Старый код — архив.** Папки `scripts/`, `scenes/`, `resources/stations/` от прототипа не трогать и не рефакторить. Увидел `Combatant`, `Limb`, `main.gd`, `scenes/battle/` — это то, что мы выбросили.
- **Не писать универсальную ECS.** Начинать с 10 объектов, а не с фреймворка.
- **Не задавать длинный список вопросов перед стартом.** Уточняй по ходу, только если реально блокирует. Автор хочет видеть движение, а не анкету.

## Справка: что доказал прототип

Тон, цикл «убежище — тоннель — станция — убежище», интерфейс, система взаимодействия, диалоги с эмоциями, шум, свет, день/ночь. Всё это работало.

**Почему уходим:** собственный рендер 863 строки, координатор станции 716 строк, всё привязано к сетке `grid_x/grid_y`, нет вертикальности, каждая новая механика требует правки рендера. Не «плохой код» — исчерпание подхода.

**Две причины, по которым прототип стал тупиком:**

1. **Собственный рендер** — движок это умеет лучше.
2. **Мир собирался кодом, а не сценами** — уровень нельзя было увидеть и подвинуть в редакторе.

Обе не повторять.

**Ловушки при чтении старого кода** (детали — `docs/05_PROTOTYPE_AUDIT.md` п.5):

- `enum Type { ENEMY, NPC, ITEM, OBJECT }` — значения позиционные, а в `.tres` записаны числа. Убрать `ENEMY` из начала — и все 9 объектов в убежище превратятся в ничто.
- `Item` лежит в «боевой» папке, но на нём держится вся предметная система. Не боевое.
- `PlayerStats` режется частично: limb-машинерия боевая, `health`/`sanity`/`humanity` — живые.
